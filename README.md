# Night War — شب‌های مافیا

سایت رسمی رویداد Night War (شب‌های مافیا). یک سایت استاتیک، موبایل‌فرست، بدون
بک‌اند، بدون build step، بدون هیچ فریم‌ورک یا کتابخانه‌ی خارجی — فقط
HTML/CSS/JS خالص (با ماژول‌های ES). هیچ Three.js، WebGL، GSAP یا هر
دیپندنسی دیگری در پروژه وجود ندارد.

---

## اجرای محلی (Local Development)

باز کردن مستقیم `index.html` با دابل‌کلیک (پروتکل `file://`) کار **نمی‌کنه**،
چون اطلاعات سناریو/نقش‌ها از `data/*.json` با `fetch()` خونده می‌شن و
مرورگرها به دلایل امنیتی جلوی `fetch` روی `file://` رو می‌گیرن. باید پوشه
رو با یه سرور محلی سرو کنید:

```bash
python3 -m http.server 8000
# یا:
npx serve
```

بعد `http://localhost:8000` رو باز کنید.

## دیپلوی (GitHub Pages)

تمام مسیرهای پروژه **نسبی** هستن (بدون `/` مطلق در ابتدا)، پس چه ریپو از
روت دامنه سرو بشه چه از یه ساب‌پث مثل `username.github.io/night-war/`،
بدون هیچ تنظیمات اضافه کار می‌کنه. کافیه پوشه رو به یه ریپو push کنید و
GitHub Pages رو روی همون برنچ فعال کنید.

## معماری — چرا این‌جوریه

هر لایه فقط یه مسئولیت داره و از بقیه بی‌خبره:

- **HTML** فقط ساختار و محتوای ثابت رو داره.
- **CSS** فقط سیستم بصریه؛ هیچ کامپوننتی رنگ یا فاصله‌ی خودش رو اختراع
  نمی‌کنه — همه از `tokens.css` میاد.
- **JS** فقط تعامله؛ هر ماژول یه مسئولیت مشخص داره (نگاه کنید به لیست بالا).
- **JSON** فقط محتواست؛ اضافه‌کردن سناریو یا نقش جدید فقط یعنی اضافه‌کردن
  یه آبجکت، بدون دست‌زدن به هیچ کد دیگه‌ای.
- **Assets** فقط محتوای بصریه؛ عکس/فونت/ویدیو با یه مسیر ثابت رفرنس
  می‌شن، هیچ‌جا هارد-کد نشدن.

### قانون رنگ (مطلق)

فقط ۴ رنگ هگز مجازن: `#000000` `#8E1616` `#E8C999` `#F8EEDF`. هیچ‌جای
پروژه — نه CSS، نه JS، نه SVG — از `rgb()`/`rgba()`/`hsl()`/رنگ‌های
نام‌دار استفاده نشده. هر حالت شفافیت به‌صورت هگز ۸ رقمی (`#RRGGBBAA`) در
`tokens.css` تعریف شده. برای اضافه‌کردن یه شفافیت جدید، اول توکنش رو
اونجا اضافه کنید.

### پس‌زمینه‌ی گرادیان زنده

`css/background.css` سه‌تا حباب محو رنگی می‌سازه که با `@keyframes` آروم
و ارگانیک حرکت می‌کنن — پشت همه‌ی بخش‌ها، `position:fixed`. چون خالص
CSS‌ه (نه JS)، با اسکرول هم متوقف نمی‌شه و هیچ هزینه‌ی فریم اضافه نداره.
تحت `prefers-reduced-motion` این حرکت خاموش می‌شه.

### اسکرول «فصل‌های روی‌هم‌سوار» (Stacked Sections)

هر بخش اصلی (`class="stack"`) با `position:sticky` بالای صفحه می‌چسبه؛
بخش بعدی که در DOM دیرتر میاد و z-index بالاتری داره، وقتی نوبتش می‌رسه
از پایین بالا میاد و بخش قبلی رو می‌پوشونه — این ترکیب `sticky` + z-index
افزایشیه، هیچ scroll-jacking یا دست‌کاری اسکرول بومی موبایل توش نیست.

**نکته‌ی مهم:** این افکت فقط وقتی درست کار می‌کنه که بخش دقیقاً یه صفحه
باشه. بخش سناریو، وقتی پنل داستان/نقش‌ها باز می‌شه، بلندتر از یه صفحه
می‌شه — اگه sticky بمونه، محتوای اضافه‌ش موقع اسکرول درست دیده نمی‌شه.
برای همین `scenario-flow.js` دقیقاً وقتی پنل باز/بسته می‌شه، کلاس
`is-expanded` رو روی خود بخش سناریو می‌ذاره/برمی‌داره؛ `motion.css` وقتی
این کلاس هست، `position` رو موقتاً `static` می‌کنه تا محتوا آزادانه
اسکرول بشه، و به‌محض بسته‌شدن پنل دوباره به حالت sticky/stacked برمی‌گرده.

### فونت

`Estedad` قفل‌شده‌ست؛ تا فایل واقعی نیومده، فالبک به `Vazirmatn` (از
Google Fonts) هست، بعدش فونت سیستم — پس صفحه هیچ‌وقت با فونت جاافتاده یا
جعبه‌ی خالی دیده نمی‌شه.

## اضافه‌کردن محتوا — بدون تغییر کد

- **سناریوی جدید**: یه آبجکت به `data/scenarios.json` اضافه کنید، با
  `roleIds` که به نقش‌های موجود (یا جدید در `roles.json`) اشاره کنه.
  کاروسل و جریان داستان/نقش‌ها خودکار می‌شناسنش.
- **نقش جدید**: یه آبجکت به `data/roles.json` اضافه کنید، بعد `id`ش رو
  از `roleIds` هر سناریویی که می‌خواید صداش بزنید.
- **عکس واقعی**: `README.txt` توی هر پوشه‌ی `assets/images/*` رو ببینید.
  هر کارت داخل یه قاب با نسبت ابعاد ثابت رندر می‌شه، پس گذاشتن عکس واقعی
  هیچ‌وقت چیدمان یا فایل دیگه‌ای رو به‌هم نمی‌ریزه.
- **ویدیوی واقعی**: `README.txt` توی `assets/video/hero/` و
  `assets/video/footer/` رو ببینید — مسیر و فرمت دقیق اونجا مشخص شده.
- **فونت واقعی**: فایل‌های `.woff2` را در `assets/fonts/Estedad/` با همون
  اسم‌هایی که در `estedad.css` رفرنس شدن قرار بدید.

## چیزهایی که هنوز placeholder ان (صادقانه، نه پنهون)

- **آرت‌ورک همه‌ی سناریو/نقش‌ها**: گرادیان جایگزین تا عکس واقعی بیاد.
- **ویدیوی Hero و فوتر**: هنوز فایل واقعی نیست؛ به‌جاش یه گرادیان استاتیک
  (`.hero-fallback-img` / `.footer-fallback-img`) نمایش داده می‌شه —
  همون چیزی که زیر `poster` هم به‌طور طبیعی دیده می‌شه.
- **فونت Estedad**: فالبک به Vazirmatn تا فایل واقعی اضافه بشه.

هیچ‌کدوم از این‌ها معماری رو می‌شکونه؛ هرکدوم دقیقاً طبق «Asset Contract»
مستندشده جایگزین می‌شن — یعنی فقط گذاشتن فایل تو مسیر درست، بدون هیچ
تغییر کد.

## تست‌هایی که انجام شده

- Syntax تمام فایل‌های JS چک شده (`node --check`).
- هر دو فایل JSON اعتبارسنجی شدن (ساختار + ارجاع roleIds به roles.json).
- کل پروژه با سرور محلی بالا اومد و مسیر تک‌تک فایل‌ها (HTML/CSS/JS/JSON/
  assets) تأیید شد که واقعاً resolve می‌شن.
- کل CSS/JS برای rgba/rgb و هگز خارج از پالت جارو شد — صفر مورد باقی موند.
- هیچ مسیر مطلق (`/...`) در پروژه نیست — امن برای هر ساب‌پثی روی GitHub
  Pages.
- هیچ ارجاع باقی‌مونده‌ای به فایل‌های سه‌بعدی حذف‌شده (Three.js، GSAP،
  Marionette، ذرات فوتر) یا به تعامل پاکت‌نامه‌ی قدیمی نیست.
- تمام custom property های CSS با تعریف واقعی‌شون در `tokens.css` چک
  شدن؛ توکن‌های مرده (باقی‌مونده از تعامل پاکت‌نامه‌ی حذف‌شده) پاک شدن.

**چیزی که نمی‌تونم از این محیط تأیید کنم:** نمایش بصری واقعی روی یه
مرورگر/گوشی واقعی — چون این محیط نه مرورگر داره نه GPU. قبل از انتشار
نهایی، حتماً روی یه گوشی واقعی تست بشه (خصوصاً افکت اسکرول روی‌هم‌سوار و
پخش خودکار ویدیو).
